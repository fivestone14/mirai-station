SNDK Payload Pipeline

From Schwab to the observer model, replayed on a recorded session's clock. Press play and watch each scan, book and minute bar fire through the pipeline, and the payload leave for the model at the moment it actually did. One payload is headed to the model: the Strikes Payload, with the History block inside it. Four never are: the Scene Payload is no longer sent whole (its clocks, price and boxes ride inside the Strikes Payload, and its walls are frozen for the next wake check), the Screen Payload feeds the dashboard, the Gate Payload is kept on disk and read by nothing, and the Regions block is computed behind the scene, checks the model’s change words and is kept in the Gate Payload — all but its `resolved` list, which since 2026-09-07 DOES ship, because it is the only evidence in the scene that a pile the model named an hour ago has since left the board. Every call’s exact message is kept too, just before it leaves. Click a box to read what it is; the payload boxes open their schema. The table under the timeline lists every file the system writes.

Anatomy of one firing

  1. 1 scan writes the diary row, payload built, gate decides 0 to about 1 s, code only
  2. 2 observer, Sonnet 5, reads the payload about 5 s on the Scene Payload in its last eras; 27 to 50 s daily median on the Strikes Payload, from 68 live calls 09-08 to 09-14; its exact message is kept just before it leaves; 180 s timeout
  3. 3 reviewer, Haiku 4.5, deletes any forecast sentence a few seconds, 40 s cap
  4. 4 read row written the sentence that stands until the next call
  5. 5 dashboard sees it the page polls every 8 s; a background tab pauses until it is shown again
